# Préparer une proposition à la Ressourcerie

Ce document prépare une candidature pour l’édition sans Remplacements de Brevet Panorama Portable au [formulaire « Proposer une nouvelle ressource »](https://grist.numerique.gouv.fr/o/forge-ressourcerie/forms/c3rKd1vPaYWeKy9ccft6UC/41). Il ne vaut ni dépôt sur la Forge, ni acceptation par la Ressourcerie. Aucune URL de ressource Forge n’a encore été créée.

## Fiche proposée

- **Titre :** Brevet Panorama Portable — sans Remplacements
- **Description (117 caractères) :** Analyser les résultats du DNB, comparer les brevets blancs et produire des bilans par élève, classe et établissement.
- **Licence du logiciel :** GNU AGPL-3.0-or-later
- **Niveau et profils :** Collège ; personnel de direction et professeurs
- **Mots-clés proposés :** Évaluation, Logiciel à installer, PDF, PIX
- **Page de présentation GitHub :** https://intelarti11.github.io/Brevet-Panorama-Portable/ ; la page à déclarer après transfert sur Forge devra utiliser les liens du dépôt Forge.
- **URL du code sur la Forge :** à créer après transfert du dépôt vers l’Atelier GitLab public.

La description commence par un verbe d’action et sa longueur a été comptée espaces compris. Le ZIP est un logiciel à installer/exécuter sous Windows x64. Ne renseignez pas une URL Forge inventée ou une adresse avec domaine unique généré.

## Vérifications requises

- [ ] Importer le projet dans l’Atelier GitLab de la Forge et publier le code en accès public. Le dépôt GitHub public prépare le transfert, mais ne remplace pas le dépôt Forge demandé par le formulaire.
- [x] Fournir la licence AGPL-3.0-or-later à la racine. <code>LICENCE</code> et <code>LICENSE</code> contiennent le même texte ; le formulaire peut référencer le fichier <code>LICENCE</code> sur la Forge.
- [x] Décrire l’usage, les imports, le stockage local et le mode d’emploi dans le README.
- [x] Documenter les polices et leurs licences ; le runtime WebView2 a une notice distincte dans l’archive.
- [x] Préparer <code>site/index.html</code> avec l’auteur, la licence, les notices et les liens de téléchargement. Les workflows GitHub Pages et GitLab Pages sont fournis.
- [ ] Après l’import sur la Forge, adapter les liens de la page vers le code, la licence et les versions sur la Forge, puis publier cette page avec GitLab Pages.
- [ ] Désactiver le réglage de domaine unique de Forge Pages pour obtenir l’adresse demandée par le formulaire. La page n’a pas encore d’adresse ; voir la [FAQ officielle de la Forge](https://docs.forge.apps.education.fr/faq/#faq::technique::domaine-unique).
- [ ] Relire les conditions d’usage de l’IA en éducation et documenter précisément l’assistance de Codex utilisée pour le développement. Cette mention n’affirme pas une certification de conformité. Voir le [cadre officiel d’usage de l’IA en éducation](https://www.education.gouv.fr/cadre-d-usage-de-l-ia-en-education-450647).
- [ ] Faire relire la proposition par l’équipe de la Ressourcerie, notamment la manière de décrire l’appartenance à la Forge avant que la ressource soit acceptée.

## Retour de la communauté

Le formulaire recommande de présenter le projet à la communauté et de recueillir des retours, en particulier sur le comportement et la compatibilité de l’application. Le salon [TestonsLaForge sur Tchap](https://tchap.gouv.fr/#/room/!FMbqDmwePWphQDroBV:agent.education.tchap.gouv.fr?via=agent.education.tchap.gouv.fr&via=agent.diplomatie.tchap.gouv.fr) est proposé pour ce type d’essai. Cette étape est recommandée pour améliorer la proposition ; aucun message Tchap n’a été envoyé par cette préparation.

## État

Le dépôt GitHub et les fichiers de présentation sont prêts pour le transfert. La candidature reste **à déposer** : il manque le projet public sur la Forge et sa page GitLab Pages avec les liens adaptés. Le formulaire de proposition n’a pas été rempli ni envoyé, et aucune approbation de la Forge n’est revendiquée.
